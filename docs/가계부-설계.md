## 2. 진입 방식 — cook/·diet/와 똑같이

이미 검증된 패턴이 프로젝트에 두 번 있다(`cook/`, `diet/`). 세 번째로 같은 길을 쓴다.

**새 파일** `money/index.html` — 머리 4줄은 `cook/index.html:7~10`과 동일:

```html
<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>
<script src="../config.js"></script>
<script src="../store.js"></script>
<script src="../support.js"></script>
```

**버튼** `index.html:76~85` 의 ⚙️ 옆, 🍳🥗 와 같은 줄에 한 칸 추가:

```
[⚙️] [💳] [🍳] [🥗] [프로필 전환]
```

- 조건: `showWallet = u.role==='parent'` (엄마·아빠방에서만 — 🍳와 동일 규칙)
- 동작: `goWallet = () => location.href='money/'`
- 돌아오기: 새 페이지 우상단 `🏡 가족 다이어리` (cook 페이지와 같은 버튼)

> ⚠️ **함정 하나 — 이름이 이미 쓰이고 있다.** `index.html:3797`의 `V.goMoney`는 **아이 용돈기입장**으로 가는 기존 함수다. 새 버튼을 `goMoney`로 지으면 아이 화면이 깨진다. 그래서 `goWallet`으로 짓는다.

**부모방 안의 💳 가계부 칩은?** → §6 질문 A

## 3. 폰용 · 웹용 (사장님 지시 4)

`cook/`·`diet/`는 `max-width:430px` 폰 전용이다. 가계부는 표·차트·보고서가 있어 넓은 화면에서 그 폭이면 낭비다. **파일 하나 + 미디어쿼리**로 처리한다(폰용 웹용 따로 만들지 않음 — 두 벌은 반드시 어긋난다).

| 화면 | 폭 | 배치 |
|---|---|---|
| 📱 폰 (기본) | ~600px | 1열. 지금과 같은 세로 스크롤, 하단 탭바 |
| 📲 태블릿 | 601~1023px | 2열 카드 그리드 |
| 💻 PC | 1024px~ | 좌측 고정 메뉴(8개 뷰) + 우측 본문 2~3열, 전체 max-width 1280px |

공통 규칙 (전역 CLAUDE.md §6):
- `word-break:keep-all` · 본문 line-height 1.6~1.8 · Pretendard
- 터치 영역 최소 44×44px (폰에서 숫자 입력이 많은 화면이라 특히)
- 금액은 천단위 콤마 + `원`, 표 숫자는 `tabular-nums`
- 표·차트는 감싼 div에 `overflow-x:auto`
- 마이너스는 유니코드가 아닌 `−` 대신 기존 코드와 동일하게 유지 (기존 `txSign`이 `−` U+2212를 쓰고 있어 **HTML 규칙에 맞게 하이픈으로 교체**)
- `@media print` — 월 보고서를 종이로 뽑을 수 있게 (배경 제거·버튼 숨김·`break-inside:avoid`)

## 4. 📄 보고서 — 로드맵 형태 (사장님 지시 3)

### 4-1. 어떤 형태인가 (로드맵 실물 기준)

로드맵의 보고서는 두 겹이다. **둘 다 가져온다.**

**① 보고서함 UI** (`로드맵/app/브라보 대시보드.dc.html:1375~1530`)

```
📚 보고서함
┌──────────────────────────────────────────┐
│ [보고서] #012        ★★★★☆    8월 15일 │
│ 2026년 7월 결산 보고서                    │
│ 지출 2,140,000원 · 예산 대비 +12% 초과   │
│                        [✓ 확인] [🗑]     │
└──────────────────────────────────────────┘
```
- **번호**(#012) — 사장님이 "12번 보고서" 로 부를 수 있게
- **★ 중요도 1~5** — 사람이 누르는 곳이 아니라 **보고서가 스스로 매긴 값** (로드맵과 동일 원칙)
- **✓ 확인 → 확인함**, **🗑 → 휴지통** (본문은 안 지우고 표시 상태만 따로 기록)

**② 본문 문체** (`로드맵/app/data/보고서/직원_경리 담당.md` 실물)

```
[확인된 것 — 7월은 예산을 넘겼습니다]
※ 지출 2,140,000원 | 예산 1,900,000원 | 초과 240,000원 (12.6%)

| 분류 | 금액 | 전월비 |
| 식비 | 780,000원 | ▲18% |
...
◐ 고정비 1,180,000원 / 변동비 960,000원

→ 판단: 초과분의 71%가 식비 한 칸에서 나왔습니다.

[주의 신호]
...

▶ 이번 달 실행: ① 식비 예산 70만 → 85만으로 현실화  ② 미납 고정비 2건 정리
```

기호 규칙: `[소제목]` · `※` 핵심수치 · `◐` 비교 · `→` 판단 · `▶` 실행

### 4-2. 월 보고서 (마감본)

- **언제**: 매달 1일 첫 접속 시 지난달분 자동 생성 (+ 아무 달이나 「이 달 보고서 만들기」 수동)
- **한 번 만들면 보고서함에 남는다** — 나중에 과거 달끼리 비교 가능
- **내용** (전부 `tx`·`budgets`·`fixed`·`fixedPaid`에서 계산, 추측 없음):

| 블록 | 담는 것 |
|---|---|
| 결산 요약 | 수입 · 지출 · 순액 · 전월 대비 |
| 어디에 썼나 | 분류별 TOP 5 + 각 전월비 (▲빨강/▼파랑) |
| 고정비 이행 | 해당 N건 중 M건 완료 · 미납 목록 · 예상액 대비 실제 차액 |
| 예산 성적표 | 예산별 달성/초과 · 초과 원인 1위 |
| 결제수단 | 🏦통장 / 💳카드 / 💵현금 비중 |
| 주의 신호 | 평소(직전 3개월 중앙값) 대비 1.5배 넘는 지출 건 |
| ▶ 실행 | 자동 도출 3개 이내 (예: 반복 초과 예산 현실화, 미납 고정비) |

### 4-3. 현재 보고서 (실시간)

- **언제**: 보고서 탭 열면 **항상 지금 값으로 다시 계산** (저장 안 함)
- 「지금 상태 저장」을 누를 때만 스냅샷으로 보고서함에 남음
- **내용**:

| 블록 | 담는 것 |
|---|---|
| 이번 달 진행 | 오늘이 N일차(전체 M일) · 경과율 대비 **지출 페이스** ("이 속도면 월말 예상 ○○원") |
| 남은 돈 | 예산별 잔액 · 소진 예상일 |
| 곧 나갈 돈 | 미납 고정비 D-day 순 · 합계 |
| 이번 주 | 최근 7일 지출 · 직전 7일 대비 |
| ▶ 지금 할 일 | 오늘 기준 실행 3개 이내 |

### 4-4. 저장 위치

`family_state` 문서에 칸 하나 추가 (다른 앱과 같은 방식):

```
moneyReports[]  {id, no:12, kind:'month'|'now', ym:'2026-07', date:'2026-08-01',
                 title, stars:1~5, summary, body, mark:{ok:false, trash:false}}
```

> **AI 없이 동작한다.** 계산과 문장 조립 모두 규칙 기반(로컬)이라 `/family-diary` 담당을 부르지 않아도 즉시 나온다. 캡처 자동 정리(기존 AI 기능)는 지금처럼 담당 호출 방식 그대로 둔다.

## 6. 사장님이 정하실 것 2가지

**A. 부모방 안의 「💳 가계부」 칩을 어떻게 할까요?**
- (a) **누르면 새 페이지로 이동** — 칩은 남고, 옛 화면 코드 835줄은 삭제 ← 권장
- (b) 칩까지 없애기 — 부모방은 자녀·스티커·설정만
- (c) 옛 화면도 그대로 두기 — 같은 걸 두 곳에서 고쳐야 해서 어긋납니다(비권장)

**B. 보고서를 누가 씁니까?**
- (a) **앱이 자동 계산** — 즉시, 공짜, 숫자는 정확. 문장은 정해진 틀 ← 권장
- (b) 클로드 담당(`/family-diary`)이 작성 — 문장이 살아있지만 사장님이 불러야 나옴
- (c) (a)로 만들고, 원할 때만 「담당에게 더 자세히」 버튼
