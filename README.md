## 처음 한 번만 하는 설정

앱은 다 만들어져 있고, **아래 4단계만 하면 가족이 같이 쓸 수 있습니다.**
순서대로 하세요. 3번까지 안 하면 로그인해도 화면이 비어 있습니다.

### 1. Supabase 프로젝트 만들기
1. https://supabase.com 접속 → 로그인 → **New project**
2. 이름은 아무거나 (예: `family-diary`), 비밀번호는 적어두세요
3. 만들어지면 **Project Settings → Data API** 에서 두 값을 복사
   - `Project URL`
   - `publishable key` (= anon key)
4. 이 폴더의 **`config.js`** 를 열어 따옴표 안에 붙여넣기

### 2. 데이터 표 만들기
1. Supabase 왼쪽 메뉴 **SQL Editor** → **New query**
2. 이 폴더의 **`schema.sql`** 내용을 통째로 복사해 붙여넣기
3. **Run** 한 번 누르기 (초록색 Success 가 나오면 끝)

### 3. 가족 계정 만들고 명단에 넣기
1. **Authentication → Users → Add user → Create new user**
   - 이메일·비밀번호를 정하세요. 이게 **가족 공용 로그인**입니다.
   - (원하면 사람마다 따로 만들어도 됩니다)
2. 다시 **SQL Editor** 에서 아래를 실행 — 방금 만든 이메일로 바꿔서:
   ```sql
   insert into family_allow (email) values ('가족계정@example.com')
     on conflict (email) do nothing;
   ```
3. ⚠️ **이 명단에 없는 이메일은 아무것도 볼 수 없습니다.** 링크가 밖으로
   새어나가도 로그인 화면만 보이는 이유입니다.

### 3-1. 로그인은 폰마다 한 번만 (2026-08-29)
- 한 번 들어오면 **그 폰에서는 다시 안 묻습니다.** 로그인 정보가 그 폰에만
  저장되어, 나중에 접속이 풀려도(토큰 만료·앱을 오래 안 열었을 때) 화면 뒤에서
  조용히 다시 들어갑니다.
- 두 번째부터는 이메일 칸이 사라지고 **「가족 비밀번호」 한 칸**만 나옵니다.
  (다른 계정으로 들어가려면 아래 작은 글씨 **다른 계정으로 들어가기**)
- **새 폰에서도 처음부터 비밀번호 한 칸만** 나오게 하려면 `config.js` 의
  `familyEmail` 에 가족 이메일을 넣으세요. 단 이 파일은 공개 저장소에 올라가므로,
  넣으실 거면 비밀번호를 길게(영문+숫자 12자 이상) 바꾸시는 게 좋습니다.
- 화면 맨 아래 **가족 계정 로그아웃**을 누르면 저장된 정보도 같이 지워집니다
  (그때만 다시 물어봅니다).

### 3-2. 비밀번호 바꾸기 (2026-08-29)
Supabase 화면에서 가족 계정 비밀번호를 직접 바꾸는 길이 없어서, **앱 안에** 넣었습니다.

1. 앱에 들어온 상태에서 화면 맨 아래 **비밀번호 바꾸기**를 누릅니다
2. 새 비밀번호를 두 번 넣고 **바꾸기** (6자 미만은 막습니다 — Supabase 기준)
3. 누른 폰은 새 비밀번호로 알아서 갈아둡니다
4. **다른 가족 폰**은 다음에 열 때 로그인 화면이 한 번 뜹니다 — 새 비밀번호를
   넣으면 그 뒤로는 다시 안 묻습니다
5. ⚠️ `.env.local` 의 `FAMILY_PASSWORD` 도 같이 고쳐야 `tools/jobs.mjs`
   (VS코드에서 캡처 정리하는 도구)가 계속 돕니다

### 4. 배포
`config.js` 를 저장한 뒤 **배포**하면 1~2분 뒤 공개 주소에 반영됩니다.

⚠️ **동기화.bat 과 배포는 다릅니다** (2026-08-14 확인):
- `동기화.bat` · 자동 올리기(10분마다) → **네이버 박스 창고**에만 올라갑니다. 백업입니다.
- **폰에 반영되는 배포**는 GitHub(`bravo8workroom-hash/family-diary`)에 push 해야 일어납니다.
  → `git push github main`

이게 갈라져 있어서 2026-08-09 ~ 08-14 닷새 동안 고친 내용이 폰에 안 나갔습니다.
지금은 `github` 원격이 다시 붙어 있으니, **고친 뒤에는 배포까지 했는지 확인하세요.**

## 가족에게 알려줄 것

1. 주소를 열고 → 가족 계정 이메일·비밀번호로 한 번 로그인 (다음부터는 자동)
2. 프로필(엄마·아빠·아이)을 고르면 내 화면으로 들어갑니다
3. 프로필별 비밀번호는 **내 정보 → 내 비밀번호** 에서 각자 정할 수 있습니다

처음 들어가면 예시 데이터(가족 이름 엄마·아빠·지혜·준선, 일정, 가계부 등)가
채워져 있습니다. **부모방 → 설정 → 데이터 전체 초기화** 로 싹 비우거나,
프로필 관리에서 이름·사진을 우리 가족로 바꿔서 쓰면 됩니다.

## AI 기능 — 담당 호출 방식

가계부 **캡처 자동 정리**는 클로드가 처리합니다.
로드맵 프로젝트의 부장 호출과 같은 구조입니다.

```
가족(폰)에서 부탁  →  대기열에 쌓임  →  VS코드에서 "/family-diary" 호출
                                        →  클로드가 처리해서 앱에 반영
```

**준비 (한 번만)**
`.env.local.example` 파일을 복사해 이름을 `.env.local` 로 바꾸고,
앱 로그인에 쓰는 가족 계정 이메일·비밀번호를 적으세요.
(이 파일은 git에 안 올라갑니다)

**쓰는 법**
1. 가족이 앱에서 캡처를 담고(한 장씩 나눠 담아도 됩니다)
   **`📮 N장 한꺼번에 맡기기`** 를 누릅니다 → 한 건으로 접수됩니다
2. 사용자님이 이 폴더를 VS코드로 열고 **`/family-diary`** 를 부릅니다
3. 클로드가 대기 중인 부탁을 읽어 처리하고 앱에 올립니다
4. 가족이 앱을 열면 결과가 들어와 있습니다

**즉시가 아닙니다.** 가족이 캡처를 올려도, 사용자님이 담당을 부를 때
처리됩니다. 대신 API 키도 추가 비용도 없습니다.

## 알아둘 것 (솔직한 한계)

- **AI는 즉시 처리가 아닙니다** (바로 위 참고). 급하게 쓸 일이 잦아지면
  Anthropic API 키를 붙여 즉시 처리로 바꿀 수 있습니다 — 구조는 그대로 씁니다.
- **동시 편집**: 두 사람이 같은 순간에 저장하면, 나중 사람의 저장이 서버의
  최신 내용 위에 다시 얹어집니다 — 서로의 기록을 덮어쓰지 않습니다.
  한 사람이 바꾸면 다른 가족 화면도 몇 초 안에 따라 바뀝니다.
- **사진**은 Supabase Storage 의 비공개 보관함에 들어갑니다. 로그인한 가족만
  볼 수 있고, 주소를 복사해 남에게 줘도 8시간 뒤 만료됩니다.
- **무료 한도**: Supabase 무료 플랜은 저장공간 1GB · 파일 1GB 입니다.
  사진은 올릴 때 자동으로 작게 줄여서(640~720px) 저장하므로 몇 년치는 넉넉합니다.

## 파일 구성

| 파일 | 하는 일 |
| --- | --- |
| `index.html` | 앱 전체 (화면 + 로직). 클로드 디자인에서 만든 원본 |
| `money/index.html` | 우리집 가계부 (내역·분석·달력·고정비·예산·자산·📄보고서). 폰/PC 반응형 |
| `cook/index.html` | 우리집 레시피 (프롬프트 만들기 · 동시 조리 · 장보기 · 타이머) |
| `support.js` | 위 파일을 브라우저에서 실행시키는 런타임 |
| `store.js` | 가족 공유 저장소 — 로그인, 서버 읽기/쓰기, 사진 업로드 |
| `config.js` | Supabase 주소와 키 (사용자가 채우는 곳) |
| `schema.sql` | Supabase에 한 번 실행하는 표·권한 설정 |
| `assets/` | 낚시도감 지도 이미지 · 캘린더/피드 꾸미기 스티커 |
| `tools/jobs.mjs` | AI 부탁 대기열을 읽고 결과를 앱에 넣는 도구 |
| `.claude/skills/family-diary/` | VS코드 담당(`/family-diary`) 지시서 |
| `.env.local` | 담당이 쓸 가족 계정 (git에 안 올라감) |
| `동기화.bat` | 더블클릭하면 네이버 박스 창고에 백업 (배포 아님 — 위 4번 참고) |

데이터는 `family_state` 표의 **한 행(JSON)** 에 통째로 들어갑니다.
앱이 데이터를 만지는 지점이 읽기 1곳 · 쓰기 1곳뿐이라 이 구조가 가장 단순합니다.
